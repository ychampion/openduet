# OpenDuet v0.3.1

OpenDuet v0.3.1 makes installation and service ownership more reliable. It
includes the personal assistant, automatic memory, recurring work and model
compatibility checks introduced in [v0.3.0](v0.3.0.md).

## Fixes

- **Windows installer reruns keep working.** Git Bash and Docker Compose can
  name the same directory differently. The installer now recognizes that
  directory by filesystem identity, preserving configuration and data while
  continuing to refuse a different installation's containers.
- **A heartbeat cannot be overwritten during service takeover.** The claim
  checks the observed nonce and precise heartbeat in the same database
  statement. Two processes starting with the same service identity cannot
  both take ownership through that race.
- **The host and browser setup is clearer.** Install the server once on a host
  that stays on, then use its web app from your other devices. Safari requires
  HTTPS for sign-in. Published images target Linux x86-64; Apple Silicon Macs
  can use the web app hosted on a supported machine.

The README and first-task guide now pin both deployment files and images to
v0.3.1. Package, service, device, mock and OpenAPI versions also report 0.3.1.

## Install

Use Linux x86-64, or Docker Desktop with Linux containers on Windows / Intel
Mac. Allow 8 GB RAM and 20 GB free disk. Install Docker Engine 28+, Compose
2.33.1+, and Git for Windows if using Windows.

Linux / Intel Mac, in Bash:

```sh
curl -fsSL https://raw.githubusercontent.com/ychampion/openduet/v0.3.1/install.sh | OPENDUET_REF=v0.3.1 OPENDUET_IMAGE_TAG=v0.3.1 bash
```

Windows, in PowerShell:

```powershell
$env:OPENDUET_REF = 'v0.3.1'
$env:OPENDUET_IMAGE_TAG = 'v0.3.1'
irm https://raw.githubusercontent.com/ychampion/openduet/v0.3.1/install.ps1 | iex
```

Open the printed setup link in Chrome or Edge, create your account, enter a
task and connect your model. The compatibility check verifies credentials,
inference and read-only tool use before continuing your saved task.

Use the [first-task guide](../GETTING_STARTED.md) for teaching preferences and
scheduling work. Configure [HTTPS or Tailscale](../DEPLOYMENT.md) for Safari or
access from other devices. Keep the host and backend running for recurring
work; closing the browser does not stop the server.

## Update an existing installation

Make a [backup](../GETTING_STARTED.md#before-updating-an-existing-installation)
first. Run the matching installation command above, setting `OPENDUET_DIR`
as well if your installation uses a custom directory. It retains local
configuration, the account and volumes. A repeat installation is not a backup.

When adding the optional browser worker later, keep `OPENDUET_REF=v0.3.1` and
`OPENDUET_IMAGE_TAG=v0.3.1`, and set `OPENDUET_BROWSER=1` on the same Bash
invocation or in PowerShell before running the pinned installer.

Native macOS installation and native Safari were not verified. The HTTPS
browser workflow was checked using WebKit on Windows. See the public
[CI](https://github.com/ychampion/openduet/actions/workflows/ci.yml) and
[image builds](https://github.com/ychampion/openduet/actions/workflows/images.yml)
for commit-specific results.

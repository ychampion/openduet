# OpenDuet v0.3.0 — your assistant, on your server

OpenDuet is an Apache-2.0 personal assistant you can install on your own server,
with a model you choose. Give it context, review its work, teach it through
corrections, and delegate recurring preparation that keeps running after you
close the browser.

## What you can do

- **Teach it through corrections.** Automatic memory can learn lasting facts and
  preferences from your own words, replace an earlier preference when corrected,
  and carry the current value into later relevant work. Review, edit or forget
  saved details in **Settings → Memory**. Explicit preference and procedure saves
  are available too.
- **Review the next useful step.** Server-side noticing checks saved source state
  for upcoming watched meetings, unresolved signals and stalled personal tasks.
  **Plan together** gathers the evidence into an editable request that stays
  unsent until you choose Send. Snooze, dismiss or pause suggestions.
- **Delegate the next run.** Use **Run this automatically** to review the
  instruction, source scope, schedule and time zone. Return to **Work** for
  results and decisions. Manage or pause routines in **Work → Recurring**.
- **Withdraw computer access reliably.** A capability change invalidates an
  in-flight permission snapshot before a device request can be queued. File-write
  verification also respects permissions from both Settings and the companion.
- **Choose and check your model.** The compatibility check verifies credentials,
  inference and an actual read-only tool call through Hermes before continuing
  your saved first request. Bounded output allowances now reach the runtime and
  native Anthropic auxiliary calls while preserving total attempt budgets.
- **Prepare more grounded drafts.** Shared instructions and writing skills now
  omit unsupported attachments, progress, promises and placeholders, distinguish
  unconfirmed details, and follow the latest style correction.

## Maintenance and security

This release includes targeted updates to pinned dependencies for validation,
mail parsing and delivery, MCP, Hono, YAML, Vite and Wrangler in response to
dependency advisories. Seven root overrides pin transitive security fixes, and
CI now audits every advisory severity. Local Hermes proof launchers honor
configured engine and Python paths and support both Unix and Windows
virtual-environment layouts.

Shutdown also waits for admitted recovery scans and refuses callbacks delivered
after stopping, keeping recovery work within the database's lifetime.

Live browser input stays with the view where it was submitted. Popup closure or
a view switch stops the remaining and queued input for that view; fresh input
can continue on the new view. Control revocation and ordinary protocol errors
remain enforced.

The full `bun audit` passed with no reported vulnerabilities. Frozen dependency
installation passed on Windows and Linux, and all 370 pinned-engine Python
checks passed without skips. All seven actual-engine integration cases, all three
standalone runtime proofs and all ten active memory conformance scenarios passed.
The full Bun suite passed: **9,955 passed, 69 conditional skips, 2 existing todo entries, 0 failed** across 945 files,
with 226,015 assertions. All baseline files and the new runner acceptance
file ran once on unchanged source. Conditional cases retain their documented
prerequisites; dedicated runtime and container jobs exercise separate opt-in
proofs. Hosted CI, image provenance, a fresh pinned installation and credential
scans are required before publication; the
[release readiness record](https://github.com/ychampion/openduet/blob/v0.3.0/docs/RELEASE_READINESS.md)
tracks those publication requirements.

## Real model evidence

Separate Anthropic `claude-opus-5-5` and Fireworks
`accounts/fireworks/models/deepseek-v4p1-flash` installations learned a writing
correction automatically, reused it in an independent task, retained it across a
backend restart, and completed a native scheduled preparation with the browser
closed and frontend server stopped. The host, API, database and workers remained
running. Customer notes were supplied examples; no mailbox was connected and
nothing was sent.

## Install v0.3.0

Use a Linux **x86-64** host, or Docker Desktop with Linux containers on Windows /
Intel Mac. Allow **8 GB RAM and 20 GB free disk**. You need **Docker Engine 28+**,
**Compose 2.33.1+**, and, on Windows, **Git for Windows**. Public images target
`linux/amd64`.

Linux / macOS, in Bash:

```sh
curl -fsSL https://raw.githubusercontent.com/ychampion/openduet/v0.3.0/install.sh | OPENDUET_REF=v0.3.0 OPENDUET_IMAGE_TAG=v0.3.0 bash
```

Windows, in PowerShell:

```powershell
$env:OPENDUET_REF = 'v0.3.0'
$env:OPENDUET_IMAGE_TAG = 'v0.3.0'
irm https://raw.githubusercontent.com/ychampion/openduet/v0.3.0/install.ps1 | iex
```

The installer creates `~/openduet`, starts the services and prints a one-time
account setup link. The app normally runs at **http://localhost:3101**. Open the
setup link, enter your first task and notes, then configure and check your model.
Your saved request continues after the check passes.

Follow the [first-task guide](https://github.com/ychampion/openduet/blob/v0.3.0/docs/GETTING_STARTED.md)
for setup, teaching a preference and scheduling work. For another device, use
[HTTPS or Tailscale](https://github.com/ychampion/openduet/blob/v0.3.0/docs/DEPLOYMENT.md),
then open the responsive app or install its PWA from a supported browser.

### Optional browser worker

After creating your account, add the browser worker with the same source and
image version. This keeps future `main` changes out of a v0.3.0 installation.

```sh
curl -fsSL https://raw.githubusercontent.com/ychampion/openduet/v0.3.0/install.sh | OPENDUET_REF=v0.3.0 OPENDUET_IMAGE_TAG=v0.3.0 OPENDUET_BROWSER=1 bash
```

Windows, in PowerShell:

```powershell
$env:OPENDUET_REF = 'v0.3.0'
$env:OPENDUET_IMAGE_TAG = 'v0.3.0'
$env:OPENDUET_BROWSER = '1'
irm https://raw.githubusercontent.com/ychampion/openduet/v0.3.0/install.ps1 | iex
```

For a custom installation directory, also set `OPENDUET_DIR` to that existing
directory. The default worker belongs to the first person's personal space;
see the [worker guide](https://github.com/ychampion/openduet/blob/v0.3.0/docs/browser-worker.md)
for another space and its controls.

## Keep control of the work

Keep the host and backend services running for background work. Automatic
capture needs a configured memory model and follows privacy and spending
settings. Start a message with **off the record** to exclude it from learning.
Your approval policy governs actions; choose **Settings → Approvals → Ask me for
everything** to review consequential actions. A draft is not a sent message.
Model providers and connected services may charge; you manage hosting, updates
and backups.

Before updating an existing installation, follow
[backup for an installer-based deployment](https://github.com/ychampion/openduet/blob/v0.3.0/docs/GETTING_STARTED.md#before-updating-an-existing-installation)
and read [upgrading and rollback](https://github.com/ychampion/openduet/blob/v0.3.0/docs/UPGRADING.md).
Re-running the pinned installer retains local configuration and volumes; it is
not a backup. Database migrations move forward, so rollback requires restoring
the matching backup.
